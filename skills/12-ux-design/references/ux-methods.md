# UX methods and heuristics

Use only methods proportionate to the change. Do not invent research results.

## Evidence sources

- Existing support issues, analytics, session observations, usability tests, and user interviews.
- Product constraints and decisions recorded in the PRD, including its Scope section.
- Current UI behavior and patterns in the repository.

## Useful methods

- Journey map: goal, context, steps, friction, system feedback, and recovery.
- Task analysis: user intent, prerequisite knowledge, actions, decision points, and completion signal.
- Usability check: can a representative user predict the next action, understand the result, and recover from failure?
- Content review: labels and messages are specific, consistent, localizable, and not dependent on placeholder text.

## Heuristic review

Check visibility of system status, match to the user's language, user control, consistency, error prevention, recognition over recall, flexibility, minimalism, recovery from errors, and help/documentation. Report a concrete failure path rather than a generic preference.

## Product signals

Choose measurable signals only when they matter: task completion, abandonment, time on task, error rate, support contacts, conversion, or accessibility feedback. Define baseline, target, observation window, and known confounders.
