# PRD Guide

Use this guide while interviewing the developer and reviewing the PRD. It is agent guidance, not text to copy into the project document.

## Interview focus

Walk the core journey from the user's perspective. Ask what the user sees, knows, does, and receives at every consequential step. Clarify the intended tone, degree of automation, user control, examples, priorities, and what the developer would protect if scope had to shrink.

## Requirements quality

Convert intent into observable behavior. Prefer concrete outcomes over vague adjectives. Every important requirement should have a testable acceptance condition. Distinguish user decisions from agent assumptions. Ask before inventing roles, screens, copy, data, metrics, or performance targets.

## Edge cases

Explore only the edge cases that could change implementation, trust, safety, or user experience. At minimum consider missing input, invalid input, empty data, slow dependencies, failed dependencies, retries, duplicate actions, permissions, interrupted work, and recovery when applicable.

## Existing products

Document current behavior before describing the intended change. Identify compatibility expectations, migration of user data, old clients, rollout stages, and behavior that must remain unchanged.
